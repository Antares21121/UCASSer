# 资料分类目录

资料目录地址为 `/resources`，入口位于共享资料板块和原生侧栏的“资料分类目录”。页面沿用 Flarum 的 Page、PageStructure、IndexSidebar 与原生 Modal，统一中文、蓝色与明暗主题。分类和来源链接保存在现有 MariaDB 中，讨论与回复仍进入原生帖子页面。

## 全新安装的初始分类

```text
校内资料
  学院（目前为空，由管理员按真实情况添加）
    必修课（添加学院时自动建立）
      课程（目前为空）
        资料链接
    选修课（添加学院时自动建立）
      课程（目前为空）
        资料链接
校外资料
  四六级
    全国大学英语四、六级考试官网
  计算机二级
    全国计算机等级考试官网
```

两条初始链接均为[教育部教育考试院的公开入口](https://www.neea.edu.cn/)，不是考试文件或虚构资料。学院和课程名称尚未由项目方确定，因此没有填充假数据。

## 安装与更新

在新克隆的开发工作区运行 `python scripts/forum.py setup`、`start`、`install` 后，需要启用扩展才能让资源页与接口生效。Flarum 2.x 核心没有 `extension:enable` 命令，启用有两条等价路径：

- 管理后台：进入后台扩展列表，启用“UCASSer 资源汇总”；
- 自动化脚本：运行 `python scripts/enable_resources.py --backend docker`（CI 与无头环境使用，内部调用管理 API `PATCH /api/extensions/ucasser-resources`，扩展 id 是 composer 包名 `ucasser/resources` 把 `/` 换成 `-`）。

启用时会执行扩展迁移，创建分类、资料、修订记录和反馈表。已有论坛合入本 PR 后，先备份，再执行 `python scripts/forum.py setup` 安装新的锁定依赖，再按上述方式启用扩展；不要重复执行 `install`。Docker 与 Windows native 均可使用，native 命令在脚本名后加 `--backend native`。

启用之后打开 `http://127.0.0.1:8080/resources`。如果本地端口不同，以 `.env` 的 `APP_URL` 为准。若扩展代码更新后新增数据库迁移，先备份，再在运行环境执行 `php flarum migrate`；普通链接和分类的增补不需要重新部署。

## 怎样维护

管理员在“校内资料”旁点击新增图标建立学院；在必修课或选修课旁新增课程，再用页面顶部“新增资料链接”填写名称、访问链接、来源与简介。资料只能放在具体课程或校外考试类别下。学院和课程旁的编辑图标可改名，资料卡片可修改与标记待核验。修改链接必须填写修订原因；“修订记录”显示字段前后值、操作者、时间与原因。分类和资料暂不提供删除按钮。

访客可以浏览、按分类及其所有子分类筛选、按名称或简介搜索；位置和搜索条件保存在 URL，分页使用真实总数。登录用户可反馈问题，管理员点击“查看待处理反馈”查看并标记处理。核验或更换链接时优先核对原始来源。

目录维护与修订历史仍仅限管理员；校园分区志愿者权限不会自动扩大到目录。自动检测链接与单独的目录志愿者授权尚未实现。

## 验收步骤

1. 访客打开 `/resources`，看到两大类、校内空学院提示、两个校外类别和真实官网链接。
2. 管理员添加一个测试学院，在其必修课下添加一门测试课程，再新增一个测试链接；刷新页面后内容仍在。
3. 管理员修改测试链接并填写修订原因，检查新链接与更新时间显示正确。
4. 普通账号尝试直接调用新增、修改接口应得到 403；登录用户反馈失效后，管理员能看到并处理反馈。
5. 搜索、分类筛选、空结果和手机宽度下的页面均可操作。

验收应在全新测试环境进行，不应把测试学院和链接写入实际使用中的数据库。

## 自动验收

```console
python tests/resource_smoke.py --url http://127.0.0.1:8080 --admin-user phase0_admin --password-file .runtime/admin-initial-password.txt
npm run test:browser
```

目录接口验收覆盖初始官方入口、分层分类、父分类包含后代、搜索与分页、危险 URL 和权限拒绝、强制修订原因、旧值新值、反馈提交与处理。浏览器验收使用原生界面，并检查高 DPI、浅深色正文对比度和手机重排。当前实际结果与远程 CI 见 [verification.md](verification.md)。
