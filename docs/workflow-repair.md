# 历史功能恢复后的流程修复

日期：2026-11-03。对应[完整 90 项改动清单](change-inventory.md)。本页记录本地实际验收和本批修复，不代表服务器已经更新。

## 本批修复

- 后台采集立即排队，公众号刷新由后台执行；重复点击不产生第二个任务。单独采集官网不请求公众号授权或刷新公众号。
- 后台自动刷新任务结果，区分全部失败、部分失败和正常检查但没有新增。中断的遗留任务可恢复处理；并发执行器不会抢同一任务。
- 检查保存的微信读书配置，不依赖临时扫码对象。网络异常与明确授权失效分开显示；普通状态检查不申请二维码。
- 读取二维码图片不会生成第二个二维码；只有发起它的运营账号能读取和推进确认。过期或被替换的二维码失效，Cookie、令牌和原始服务响应不返回浏览器。
- 订阅前通过原文核验发布者，再添加真实订阅，不创建虚拟精选文章订阅。三处已审核更名保留原来源名称与识别。
- PHP 采集使用 UTC，与终端导入一致；暂停订阅不刷新。单个公众号导入失败回滚本轮写入；明确失效时停止后续请求，未执行账号不伪报成功。
- 公众号刷新允许后台所需等待时间；官网连接失败后，同一轮不对同一域名重复等待。错误仍计为失败，下轮重试。
- 官网快照校验真实日期，导入和审计在事务内完成，后续条目出错不留下部分导入。
- 新建课程、资料返回已创建记录；新学院正确关联资料目录，创建审计不再误写更新。课程编辑保留简介、外部编号和分类；清空必填名称返回校验错误。
- 课表订阅要求已确认账号和真实课程安排，重复订阅不重复写入，不同账号之间不可互相读写。
