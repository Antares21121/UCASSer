# 开发路线图与交接

## Phase 0：基础架构（开发工程已完成）

已实施：沿用上游 Flarum 2.x 的 Composer 骨架、锁文件、Docker 开发配置、独立生产配置骨架、Windows 便携工具、环境桥接、安全初始化、管理命令、数据库/文件持久化、备份恢复、健康检查、中文文档和 CI。当前 RC 只用于开发，正式生产等待稳定 2.x。

已实际验证：Windows 与 GitHub Actions 的 Ubuntu Docker 安装、首页/API、停止/重启、数据库记录、上传文件、私有路径拒绝、真实备份、隔离数据库恢复和重复恢复拒绝；Docker 构建与 Nginx 配置检查通过。具体证据见 verification.md。

尚待验证：生产 HTTPS 与只读卷权限、外发邮件和生产恢复。尚未配置：自动备份调度、异地存储、日志告警、正式域名与服务器。当前工程基线可交接；正式上线不是本阶段的完成事实。

## Phase 1：校园论坛基本业务

| 模块 | 可直接接手的任务 | 验收要点 |
|---|---|---|
| 校园信息聚合 | 设计 tags 分区、来源字段/发帖模板、信息有效期、人工纠错与失效标记 | 公开来源可追溯，不默认抓取封闭聊天记录 |
| 公共资料索引 | 建立资源链接、课程/年份标签、授权声明和失效反馈，优先索引而非复制托管 | 权利与隐私可追溯，可导出与迁移 |
| 课程测评 | 设计课程标识与测评模板，试行基本审核 | 不提前实现排名算法，区分事实与主观体验 |
| 问答与求助 | 建立求助分区、解决状态和基础标签，评估维护中的兼容扩展 | 问题状态清楚，成员可举报 |
| 用户组与分区权限 | 设计权限矩阵、校园认证的最小数据流程，配置 tags 权限并测试越权 | 访客/成员/审核员的读写边界可验证 |
| 匿名与隐私 | 明确可见身份边界、滥用处理和数据保留规则，再选择兼容扩展或最小开发 | 没有完整机制前不对外承诺匿名保护 |
| 志愿审核与治理 | 明确轮值、申诉、分区审核权限及可公开治理记录 | 志愿者不获得部署权限，操作可审计 |

一期先选择和验证维护中的中文语言包；Phase 0 仍为官方英文界面，中文开发文档已经提供。

优先三个任务：

1. 评估正式 Flarum 2.0 与中文语言包/基础扩展兼容性，建立从当前 RC 升级到正式 2.x 的回归方案，正式发布与验证前不进行生产部署。
2. 完成校园分区、注册政策和最小权限矩阵，在后台配置并做访客/成员/审核员越权测试。
3. 建立公共资料与校园信息的发布模板、来源/授权要求和失效反馈，先试点小规模志愿维护。

## Phase 2：完善治理与长期维护

- 根据一期真实反馈完善匿名隐私、资料索引检索和内容修订流程。
- 建立异地加密备份、自动调度、告警、恢复演练和值班交接。
- 评估附件存储、内容导出和审计记录的保留/公开政策。
- 只在实际容量和性能数据提出需求后扩展基础设施。

不纳入当前范围：复杂 Wiki、课程评价算法、聊天记录抓取、订阅推荐、广告、付费会员/内容墙、微服务、Kubernetes 或无证据的分布式方案。

## 待决策

论坛正式名称、域名、生产机器与预算；校园认证方法；公开/校园限定分区范围；匿名和审核规则；资料版权处理；维护者与恢复负责人；SMTP；备份目的地、保留期与加密密钥保管。全部允许独立配置，未填入虚构生产值。
