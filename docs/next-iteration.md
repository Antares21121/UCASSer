## 优先级 1：视觉与使用体验

| 工作 | 验收标准 |
|---|---|
| 十板块逐页精修 | 首页、分区列表、详情、发布、编辑、空状态和错误状态采用一致的间距与控件规则；保留各板块的内容结构差异 |
| 字体与主题对比度 | 逐项检查顶栏、侧栏、辅助文字、标签、占位符和禁用状态；覆盖浅色、深色、高对比度及系统强制颜色，不能只检查正文 |
| 移动与 DPI | 真机检查 320–1440px、DPR 1/1.25/2、浏览器 200% 缩放及软键盘；长标题、长网址、中文输入和目录路径无裁切或横向溢出 |
| 导航与侧栏 | 从桌面直接缩到手机时确认原生菜单过渡无残影；长侧栏可滚动，选中项明确，返回首页后不残留返回按钮 |
| 信息流与演示内容 | 交错生成各分区帖子，使默认信息流更自然；回复按问题语境撰写，演示标识明确，重复注入不重复创建或跳过未完成的互动 |
| 可访问性 | 完成键盘、读屏、焦点恢复、表单错误定位与触控尺寸人工检查，补足自动测试未覆盖的控件 |

## 优先级 2：性能与维护

1. 在冷缓存、弱网及大数据量下记录列表和详情加载耗时、查询数量、首屏及布局偏移。当前已批量加载列表元数据并隔离旧请求；后续优化由测量结果决定。
2. 补齐目录在多级分类、资源分页、权限变化、删除/失效来源和并发编辑时的验证；评估版本冲突保护及分类维护的撤销流程。
3. 为备份恢复增加资料目录条目、修改记录、反馈和演示清单的一致性校验；现有恢复已验证 SQL、文件、源码与校园业务统计。
4. 将浏览器验收数据与日常演示实例隔离，避免每轮测试重新污染可供体验的信息流。保留开发脚本的环境限制、备份和精确识别条件。
