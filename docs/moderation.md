# 治理、审核与志愿交接

社区公约位于 `/campus/rules`，已生效版本与维护记录位于 `/campus/governance`。管理员发布新版本而不覆盖旧条目，可设定 UTC 生效时间。公益、无广告、无付费墙、版权、隐私与友善交流写入初始公约；正式运营人员应审核适用措辞后发布更新。

1. 成员在帖子菜单选择「举报并跟踪处理」，正文附带必要可核验线索；讨论、评论或用户行为必须关联本人可见的讨论。重复进行中的举报被拒绝，应补充原记录。
2. 处理人员在 `/campus/cases` 查看获授权分区队列。状态依次为待处理、处理中、待补充、已处理或不予处理。操作需当前版本与 5–500 字理由；并发旧版本不会覆盖新处理。
3. 先核查、要求修改或记录说明。隐藏与恢复保留正文；永久删除、封禁与解封只允许管理员。永久删除须明确勾选确认。举报本身不触发处罚。
4. 公开给当事人的处理理由不能包含举报者身份或证据中的个人材料。双方收到一般性的站内结果通知；当事人只看到结果，不看到他人的私有材料。
5. 举报者或被举报者可对已处理/不予处理提交申诉。复核必须由原处理人以外且不涉及该举报的人员执行，保留复核过程和理由。

信息整理者维护来源、时间、分类与失效状态；资料维护者核验许可和链接；分区志愿版主处理分区秩序；技术维护者通过 Git、部署和恢复协作；社区协调者维护规则与跨分区事项。这些职责是可兼任的工作分工，不自动授予全站管理员或服务器权限。

管理员在扩展后台为具名成员授权具体分区，记录理由。每次交接应核对待办举报与失效反馈，告知职责、处理尺度与复核人，授予接任人员，再撤销离任者所有分区授权；撤销后 API 立即拒绝其处理请求。不要共享管理员账号。公开职责/招募/交接说明由管理员发布，授权人身份不自动公开。

作者可编辑自己的结构化内容，保留历史。分区维护者可维护结构化字段与状态，正文由作者或管理员修改。精选仅维护者可改，原生置顶/锁定服从 Flarum 权限。信息过期仍保存，不自动删除讨论。

来源纠错、链接失效反馈在内容详情页提交，成员只能查看本人反馈。获授权维护者在详情页以理由处理，反馈者收到站内通知。涉及侵权或隐私的严重投诉使用完整举报流程，以保留申诉与复核。

上线前指定值班与复核负责人、响应时限和私有投诉联系人。在这些人员尚未确定前，开发示例不代表真实受理承诺。
