# 整站部署预演

网站能打开只说明访问入口恢复；本工具为实际部署准备独立副本，不会切换公网网站。它使用线上数据库的快照和独立运行卷，不用开发数据库覆盖线上内容。

## 会做什么

- 只读获取现有 app/db/web 的镜像和运行卷，在源目录的同级新建独立工作区。
- 创建独立库名、随机数据库密码、全新卷及 Compose 项目。已有目录、容器或同名卷均拒绝覆盖。
- 源数据库使用一致性转储，源运行卷以只读方式复制。原站保持运行，不停止原站容器、调度或执行器。
- 复用现有镜像与依赖，不在小服务器上重建镜像。候选版本必须与源实例具有相同 composer.lock。
- 副本内禁用邮件和注册，清除副本令牌及待执行队列，不复制文件会话、缓存和日志；保留原站业务数据和用户关系的数据库副本。
- 应用与数据库处于内部网络；前端单独连接预览网络，仅绑定主机 127.0.0.1。没有采集 runner，也不安装定时任务。
- 只在副本启用私信扩展、运行迁移和校园初始化、清缓存；保存源与副本的表计数并检查副本 API。

它不会授予线上运营角色、发布信息、导入待迁移资料、迁移公众号登录状态或修改公网反向代理。部署预演成功也不等于整站迁移完成，后续仍按[整站对账清单](instance-reconciliation-2026-10-30.md)逐项验收。

## 使用

Python 3.11+、Git 和 Docker Compose 必须可用。实例使用当前仓库的 compose.yaml、环境桥接 config.php 和命名运行卷。目标必须是源目录同级的新目录，目录名等于以 ucasser-stage- 开头的新项目名。

先预览计划，不创建环境：

```bash
sudo python3 scripts/stage_instance.py \
  --source-root /opt/ucasser-test --env-file .env.test \
  --stage-root /opt/ucasser-stage-reconcile --project ucasser-stage-reconcile
```

加 --create 才创建副本。默认副本使用现有源码提交；要比较某个候选提交，额外传入 --ref 完整提交SHA，且该对象必须已在源仓库中获取。

```bash
sudo python3 scripts/stage_instance.py \
  --source-root /opt/ucasser-test --env-file .env.test \
  --stage-root /opt/ucasser-stage-reconcile --project ucasser-stage-reconcile \
  --ref 72ad6cf54289bce17902d83704887a184eb7fd00 --create
```

需要至少 2 GiB 空闲磁盘；Linux 主机需要至少 512 MiB 可用内存。副本数据库／应用／前端分别限制为 256／192／32 MiB。网页仅在服务器本机 http://127.0.0.1:18081 可访问，不应直接把包含用户副本的环境开放到公网。

成功报告位于目标工作区 .runtime/stage-report.json。该目录另含数据库快照及独立凭据，仅供本机维护，不提交 Git、不粘贴进聊天。报告只包含项目身份、表计数、扩展和快照指纹，不输出账号密码或私信正文。

失败时保留副本供检查，原站不自动切换。不要重复对同一目录导入；修复原因后使用新的项目和目录，或先人工核对既有副本。工具没有递归删除或在线回滚操作。

## 后续验收

核对源与副本的正式课程、学院、资料分类、既有待审信息及用户数量；检查启用扩展、权限与实际页面，并在副本预演业务键增量迁移和重复执行。正式上线另作备份及受控切换，不能仅凭 API 返回 200 就完成上线。
