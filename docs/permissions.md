# 角色与权限矩阵

校园限制同时覆盖原生讨论、标签、API、搜索、通知、个人中心和导出，并叠加 Flarum 默认权限。认证只赋予 campus.verified；志愿身份只赋予 campus.volunteer 并校验具体分区，不加入管理员或全站 Moderator 组。

| 角色 | 权限边界 | 实施状态 |
|---|---|---|
| 访客 | 只读公开且开放分区，不能写入 | 后端原生与自定义查询过滤 |
| 注册成员 | 可见分区发帖/回复/举报；编辑本人；收藏和个人数据仅本人 | 原生权限加校园策略 |
| 校园认证成员 | 增加认证分区读取；不增加管理权限 | 自愿验证、材料清除、撤销/重申请 |
| 志愿审核员 | 仅授权分区隐藏/恢复和举报；不处理本人相关举报 | 分区授权及撤销立即生效 |
| 内容维护者 | 授权分区字段、来源、状态、精选；正文由作者或管理员编辑 | 结构化内容、课程及许可保留的资料转换 |
| 论坛管理员 | 验证/角色/分区/分类/审计；严重处置与公开治理 | 独立具名账号，删除须明确确认 |
| 部署维护者 | 镜像、数据库、备份和故障恢复 | 运维角色原则，非 Flarum 内建组 |

遵循最小权限，普通用户与志愿者不获得管理员身份。论坛后台管理权限与服务器/Docker 维护权限分离，管理员不默认拥有任意 Composer 包安装能力；未引入扩展管理器。

问答采纳仅提问者可操作。被第三方隐藏的内容普通作者不能借编辑恢复。封禁禁止原生及校园写入，保留申诉/个人数据权利。最终申诉复核须由原处理人以外、非本人相关且获授权的人员执行；管理员也遵守回避要求。资料转换不能扩大可见范围。验证材料与全站审计仅管理员可见；个人导出下载要求登录且属于申请者或管理员。

原生点赞、置顶、锁定、注册、上传等权限仍在 Flarum 后台配置。匿名发布关闭，不抓取聊天记录，不新增附件托管。正式验证标准、运营人员与保留期限由维护者确定，见 [隐私](privacy.md) 和 [治理](moderation.md)。
