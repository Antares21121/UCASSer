# 用户组与一期权限原则

Phase 0 已安装 Flarum 及内置 tags、approval、flags、suspend 等扩展，但没有创建校园专属用户组、分区政策或匿名系统。当前真实权限是 Flarum 初始默认权限，必须由管理员在邀请用户前核对。

| 拟采用角色 | 一期原则 | Phase 0 状态 |
|---|---|---|
| 访客 | 只读公开分区；不可查看成员私有内容 | 采用 Flarum 默认访客能力，策略待配置 |
| 注册成员 | 发帖、回复、举报；只编辑自己的内容 | 默认成员能力，窗口与权限待评估 |
| 校园认证成员 | 进入需认证的分区；认证数据尽量少收集 | 认证与用户组尚未实现 |
| 志愿审核员 | 仅审核被分配分区；不得管理依赖、秘密或全站账号 | 分区权限和审核记录待实现 |
| 内容维护者 | 维护公共资料索引、来源和失效状态 | 资料索引模块尚未实现 |
| 论坛管理员 | 管理论坛设置与权限；少数具名账号 | 本地仅初始化一个管理员 |
| 部署维护者 | 镜像、数据库、备份和故障恢复 | 运维角色原则，非 Flarum 内建组 |

遵循最小权限，普通用户与志愿者不获得管理员身份。论坛后台管理权限与服务器/Docker 维护权限分离，管理员不默认拥有任意 Composer 包安装能力；未引入扩展管理器。

一期需要建立可复核的分区权限矩阵，验证匿名与审核时的身份访问范围，以及禁言、申诉、账号恢复与治理记录保留规则。半中心化治理依赖规则、透明记录和可交接维护，不通过共享管理员密码实现。

校园认证方法、未成年人参与、匿名责任边界、治理记录公开尺度都属于待决策事项。本阶段不抓取微信群、不预建实名资料表，不宣称已提供这些能力。
