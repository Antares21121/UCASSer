# 运营后台与新版前端交接

本轮把日常运营工作集中到 `/campus/control`。运营者使用普通论坛账号登录，再由部署者通过 `campus:operator` 单独授权；无需成为 Flarum 管理员。初次安装、扩展设置及不可逆的删除或封禁仍通过底层平台权限管理。具体命令和部署步骤见[运营后台](control-console.md)。

## 已实现

- 独立运营工作区包含一键采集和任务状态、官网快照导入、信息审核、来源登记与启停、校园身份审核、举报及申诉处理。所有写入接口在服务端检查运营权限；运营账号不能操作 Flarum 的系统设置。
- 一键采集创建排队任务，由 `ucasser-collection-worker.timer` 每分钟检查并执行一项；定时自动采集仍由原有 `ucasser-aggregation.timer` 管理。新内容只进入待审队列。
- 论坛前端改为校园红、浅蓝和白色的视觉主题；首页新增搜索框和常用入口。页面明确标明这是同学共建的独立社区。
- 私信编辑器只显示文本输入、发送及图片按钮。图片存入非公开目录，上传者和所属私信会话成员可读取。

## 接手后的部署顺序

1. 备份测试站并更新 `2.x` 代码，再按现有部署说明重启、迁移和清缓存；勿在生产数据上运行开发烟测。
2. 安装并启用 `deploy/systemd/ucasser-collection-worker.service` 与 `.timer`，检查任务日志。
3. 注册专用普通账号，运行 `campus:operator 用户名` 授权，然后访问 `/campus/control`。
4. 测试一键采集、待审队列和来源状态。阿里云测试站此前连接社科大官网超时；遇到同样问题，从可访问官网的本地电脑生成快照并在后台导入。公众号需要独立采集器授权，不会因来源登记自动接通。

## 验收记录与边界

本地 Docker 开发实例已完成 PHP 语法、Python 单元测试、运营账号权限与采集排队烟测、私信图片会话隔离烟测，以及运营后台桌面和手机宽度浏览器测试。GitHub CI 会再次执行这些检查。服务器部署及公众号授权需在服务器环境单独验证；本地测试通过不代表云服务器已更新。
