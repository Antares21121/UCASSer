# 信息汇集：首轮设计与实现边界

## 要解决的事

学生需要在一个独立于论坛讨论和资料目录的信息流里查找校园通知、活动与机会，并看清来源及核实状态。登录成员可提交公开链接或无链接线索；管理员先审核，再决定是否发布。首轮只自动采集一个已登记的公开网页栏目，但数据结构允许以后接入其他网站、公众号的合规接口和人工渠道。

## 页面与操作

- `/campus/aggregation` 为独立信息流。标题、简短摘要、来源性质、核实状态、发布时间和来源数量是列表的主要信息；可见范围由服务端执行。手机上重排为单列，投稿入口保留。
- `/campus/aggregation/submit` 是登录成员的投稿表单。投稿人填标题、摘要、来源说明、可选公开网址，并选择来源是公开网页还是非公开线索、是否署名。提交后显示待审核状态，不立即对外展示。
- `/campus/aggregation/review` 仅管理员可用。候选信息逐条显示来源、内容，以及同网址已关联的条目编号；可发布新条目、按编号合并到现有条目、批准变更或拒绝。审核动作记录管理员与时间。
- 未核实信息可以在任何类别发布，但信息流中明确标注“未核实”；未核实条目不提供直接报名、缴费等操作按钮。公开网址来源的条目可给访客看，非公开渠道线索只给登录成员看；原聊天内容不存入公开记录。
- 投稿人自行选择是否署名。未署名时公开页面不透露账号，管理员仍可在待审队列追溯投稿人。

## 数据与处理

1. 来源登记表保存名称、网址、适配器、官方／非官方性质、公开／成员可见范围和启用状态。只有已登记的公开网址会被抓取。
2. 抓取器只提取标题、日期、简短摘要、原链接和内容摘要指纹；不复制完整文章或附件。重复运行不生成相同候选。
3. 候选表保存爬取结果或用户投稿，状态为待审、已发布或已拒绝。相同网址内容变更产生新的待审候选，原公开条目保持不变。
4. 发布表保存管理员批准的字段和核实状态。不同网址指向同一事项时由管理员合并，来源关系保留；不凭相似标题自动合并。
5. 公共 API 仅返回已发布且当前访问者有权查看的条目及来源；待审、拒绝、投稿账号和审核备注都只通过授权接口返回。

## 首轮验收

- 一个学校公开栏目能够被实际抓取；断网、页面结构变化或来源不可达只记录错误，不发布虚构内容。
- 登录成员可以提交有链接或无链接线索，访客不能投稿；提交后只有投稿人和管理员能看到待审状态。
- 管理员可以发布、拒绝、将另一候选合并到已有条目，并核准已发布网页的后续修改；公开条目保留来源关系。
- 相同网页重复抓取不重复入队；网页变更进入复核队列；列表分页与可见范围在服务端生效。
- 不依赖 CSS 装饰传达“未核实”“待审”状态，键盘、窄屏、空状态与失败提示可用。

首轮只验证完整小链路。定时调度由部署环境调用同一个命令；公众号和微信群不自动读取，正式运营前再确定来源接入方式与保留期限。

## 开发环境操作

更新代码、前端构建并备份已有数据库后，运行 `python scripts/campus.py migrate`（Windows 便携环境加 `--backend native`）。随后执行 `python scripts/aggregation.py --limit 5`，其 Docker 与便携环境选项相同。新公告只进入管理员待审队列；管理员从 `/campus/aggregation/review` 核对并发布，访客从 `/campus/aggregation` 查看。登录成员从 `/campus/aggregation/submit` 投稿。

默认来源为[中国社会科学院大学教务处通知公告](https://jw.ucass.edu.cn/tzgg.htm)。抓取器只接受该站 HTTPS，单次最多取 10 篇、每页最多读取 1 MB，15 秒后终止请求。暂不内置定时任务；部署者确认抓取频率后再配置调度。来源页面不可用时可稍后重试，记录会显示在管理员页面，不会自动发布。
