# 原生页面与蓝色主题

校园界面沿用锁文件里的 Flarum 2.0.0-rc.8。首页、顶栏、信息流、讨论正文和个人资料使用核心组件，再通过校园扩展增加业务能力；不修改 vendor。

| 入口 | 原生基础 | 校园扩展 |
|---|---|---|
| `/`、`/campus` | IndexPage、WelcomeHero、IndexSidebar、DiscussionList | 十个紧凑分区入口、优先呈现原生信息流、正文摘要与板块元信息 |
| 顶栏和手机导航 | HeaderPrimary、HeaderSecondary、OverflowingList、原生导航抽屉 | 首页、校园信息、资料、问答、课程经验；保留搜索、主题、通知和账号菜单，增加上下文发布入口 |
| `/t/campus-*` | 原生标签分区、IndexPage、DiscussionListItem | 十板块独立信息结构、原生 Hero 子类、快捷分类/状态筛选及当前板块发布默认值 |
| `/campus/records`、`/campus/search` | IndexPage 子类、原生排序、DiscussionList 和加载更多 | 类型、分类、状态、课程、学期与日期筛选 |
| `/d/:id` | DiscussionPage、PostStream、CommentPost | 来源、版权、状态、课程字段、收藏、私有纠错、反馈处理和修订记录；回答采纳和整理资料 |
| `/campus/record/:id` | 跳转原生讨论 URL | 兼容已有收藏、通知和关联链接，先检查记录访问权限 |
| 发布和编辑 | DiscussionComposer、TextEditor、ComposerPostPreview | 校园字段、接口校验、版本冲突、保存后跳转原生讨论；保留原生工具栏、预览、收起、全屏和草稿丢弃提醒 |
| `/campus/me` | UserPage、UserCard、个人资料侧栏 | 本人发布、收藏与回答，保留公开资料和账号设置入口 |
| 身份、课程目录、举报、公约和治理 | PageStructure、IndexSidebar、Modal | 核心没有对应业务页面，扩展在原生框架内提供表单、分页、权限和错误状态 |
| 后台 | 原生 ExtensionPage、Button 和扩展入口 | 分区、分类、验证、授权及审计标签页 |

信息流是一行一帖的原生列表：标题在上，类型、状态、作者和时间在其后，正文摘要通常两行，互助板块最多三行，回复数量保持在右侧。帖子链接、已读状态、排序、分页、手机滑动和管理操作仍由核心负责。摘要取自原生 `firstPost` 关系，经权限过滤，以纯文本渲染。

## 十板块的阅读与操作

| 板块 | 信息流 | 详情与主要操作 |
|---|---|---|
| 资讯与活动 | 日历标识、时间、地点、主办方、有效/结束状态 | 活动信息与来源分组，有效内容提供报名入口 |
| 实习就业竞赛 | 机会类别、单位、截止时间、参与条件 | 申请信息、来源、申请链接 |
| 学术与志愿 | 日程标识、时间地点、主办方 | 参与条件、来源、报名入口 |
| 生活与互助 | 原生作者、需求/地点、较完整摘要、回复 | 互助说明、解决状态、原生回复 |
| 二手与出行 | 左侧识别线、供需/地点、成交或失效状态 | 实际供需与出行字段，保留联系方式授权提示；不虚构价格或图片 |
| 共享资料 | 文档标识、课程/主题/版本/核验时间 | 访问资料与备用链接、出处、版权或使用说明 |
| 课程经验 | 课程名称、学期和三个真实 1–5 评分 | 分项评分刻度、学习建议、课程目录与真实 SQL 样本统计 |
| 问答 | 回答数或采纳标识、待答/讨论/解决状态 | 状态进程、问题背景、跳到已采纳答案；提问者采纳/取消 |
| 闲聊讨论 | 原生头像、自然摘要、最近互动 | 原生讨论、回复和互动 |
| 公告治理 | 公告标识、来源及发布时间 | 正式治理版本与生效时间在公开治理页面，板块直接提供入口 |

缺失的可选字段不生成占位数据。信息流的回复数、日期、评分与状态来自实际 API；所有板块保持蓝色主题，以结构和阅读重点区分。各板块 Hero 的名称与简介遵循后台维护值。

资料详情突出合法访问入口，版权说明保持可见；问答已采纳按钮读取可见原生帖子并定位其 URL。编辑、收藏、纠错和版本历史为次级操作；反馈处理与历史正文仍按权限显示。发布沿用原生 Composer，自动选择当前分区和合适分类，必要字段先填写，可选字段按需展开；正文格式、预览、收起、全屏和草稿确认保留。

## 语言、主题与细节

校园扩展注册 `zh-Hans`，默认简体中文；覆盖核心前台与账号、排序、回复、工具提示、无障碍标签及已安装互动扩展。保留原有英文包，用户可切换语言。核心 DayJS 时间本地化；中文标题输入与「标题格式」工具提示使用不同标签。中文文件显式解析核心引用，避免跨语言回退造成部分按钮仍为英文。

十板块采用同一套已安装 Font Awesome 图标。setup 仅一次将校园默认毕业帽图标替换为对应图标，已有自定义图标保留。图标尺寸、背景、圆角和辅助文字统一；纯装饰图标隐藏于读屏，按钮保留文字与辅助标签。320/390px、键盘焦点、原生导航抽屉、深色主题和减少动态偏好都有对应样式。

主题使用原生外观设置 `theme_primary_color`，新环境默认蓝色 `#2563eb`。`campus:setup` 只在首次主题初始化时替换上游默认色；旧校园分区默认青色迁移为蓝色，管理员自定义颜色保留。校园 LESS 引用 `@primary-color` 和原生明暗主题变量，按钮、链接、欢迎区、选中状态和分区入口保持一致。后续在原生后台「外观」修改主题颜色。

校园筛选通过原生 `/api/discussions?filter[campus]=…` 查询；`SearchQuery` 与现有搜索接口共享 `whereVisibleTo` 权限查询。原生排序将筛选写入 URL，页面会还原这些条件，切换排序不会丢失内容类型。`campusRecord` 只返回可见记录的公开字段和当前账号操作权限，不包含正文历史、验证材料或私有反馈。

日期输入与详情显示使用北京时间，提交时转换为 UTC；日期范围筛选使用接口的 UTC 自然日并在界面标注。网络失败保留输入，课程查找只自动请求一次，后续由用户重试。保存成功后即使详情读取失败也结束提交，避免重复发布。

## 开发与构建

源代码在 `extensions/campus/js`，样式在 `extensions/campus/resources/campus.less`。依赖版本沿用仓库锁文件：

```console
npm ci
npm run build
python scripts/campus.py migrate --backend native
python scripts/forum.py start --backend native
```

已有数据库先执行 `python scripts/forum.py backup --backend native`。迁移命令执行 setup 并清缓存；本轮没有新增数据库迁移。Docker 使用对应命令的 `--backend docker`。本地环境完整说明见 [development.md](development.md)。

Flarum 2.x 的登录弹窗、编辑器和评论组件采用异步模块加载。源码在 `js/` 根目录，因此 webpack 的 `autoChunkNameLoader` 必须覆盖该目录；否则静态构建可成功，首次打开弹窗或编辑器却会失败。扩展不得覆盖原生 Composer 的 `onTextEditorBuilt` 回调，等 `editorReady()` 后再设置校园辅助属性。

提交源代码和 `js/dist`，不提交 node_modules、vendor、运行缓存、凭据、浏览器截图或测试数据库。Chrome 验收：

```powershell
$env:FORUM_BROWSER_CHANNEL='chrome'
npm run test:browser
python tests/campus_smoke.py --backend native --phase 11
```

浏览器测试和权限接口测试顺序执行，避免测试临时调整分区权限影响浏览器流程。当前结果与远程 CI 证据见 [verification.md](verification.md)。生产仍等待稳定 Flarum 2.x，并单独验证 HTTPS、外发邮件、备份恢复和运维配置。

课程维护按钮位于目录页顶部，保存后自动定位该课程；原生错误提示移到内容上方，避免遮挡编辑器的提交和重试按钮。访客进入个人空间、身份、维护与举报页面先显示原生登录入口，不发送注定失败的受限请求；手机菜单打开时，提示层位于菜单下方，导航仍可操作。
